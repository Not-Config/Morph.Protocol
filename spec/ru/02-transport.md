# Morph Protocol v0.1 — Транспорт

> Это перевод канонической англоязычной спецификации. В случае расхождений приоритет имеет версия из `spec/en/`.

Morph Protocol v0.1 использует WebSocket в качестве realtime-транспорта.

## Требования к транспорту

Производственные соединения MUST использовать WebSocket поверх TLS (`wss://`). TLS 1.3 SHOULD использоваться везде, где он поддерживается инфраструктурой развёртывания.

Незашифрованный WebSocket (`ws://`) MUST NOT использоваться в недоверенных сетях. Реализации MAY разрешать его для локальной разработки или изолированных тестовых сред.

## Логическая независимость

Логический Morph Protocol не привязан навсегда к WebSocket. Семантика пакетов, состояние соединения, команды, результаты и события определяются независимо, чтобы будущие версии могли поддерживать такие транспорты, как QUIC, без переработки прикладной модели.

## Кодирование

Пакеты Morph Protocol v0.1 кодируются как текстовые UTF-8 JSON-сообщения.

Каждое WebSocket-сообщение MUST содержать ровно один полный пакет Morph Protocol.

Реализация v0.1 MUST NOT разбивать один пакет Morph на несколько WebSocket-сообщений прикладного уровня и MUST NOT объединять несколько пакетов Morph в одно WebSocket-сообщение прикладного уровня.

## Закрытие соединения

Любая сторона может закрыть WebSocket-соединение, если:

- другая сторона нарушает state machine протокола;
- повторно получаются некорректные пакеты;
- аутентификация завершилась неудачно согласно политике сервера;
- превышен heartbeat timeout;
- произошла невосстановимая ошибка протокола;
- сторона завершает работу.

Когда это практически возможно, сторона SHOULD отправить пакет Morph `ERROR` до закрытия транспорта.

## Размер сообщения

Точный максимальный размер пакета в v0.1 определяется конкретным развёртыванием. Серверы MUST устанавливать конечный максимальный размер и SHOULD возвращать ошибку протокола перед закрытием соединения, если пакет превышает допустимый размер.

Крупные бинарные объекты, например медиа-вложения, не передаются напрямую как JSON payload в realtime-протоколе. Транспорт медиа будет определён отдельно.
