# Morph Protocol v0.1 — Базовые пакеты

> Этот документ является частью канонической русскоязычной спецификации Morph Protocol. При расхождениях с переводами приоритет имеет версия из `spec/ru/`.

Morph Protocol v0.1 определяет небольшой набор операций верхнего уровня. Прикладные действия передаются внутри пакетов `COMMAND` и `EVENT`, а не получают отдельные верхнеуровневые opcodes.

## Основные операции

Начальный набор операций:

- `HELLO`
- `HELLO_ACK`
- `AUTH`
- `READY`
- `COMMAND`
- `RESULT`
- `EVENT`
- `ACK`
- `RESUME`
- `HEARTBEAT`
- `ERROR`

## Общие правила

Каждый пакет MUST быть JSON-объектом, содержащим поле `op`.

Неизвестные поля верхнего уровня SHOULD игнорироваться получателем, если согласованная capability не требует иного поведения. Это позволяет расширять протокол добавлением новых полей в пределах одной версии.

Неизвестные значения `op` MUST приводить к ответу `ERROR` с кодом `UNKNOWN_OPERATION`.

## COMMAND

`COMMAND` просит сервер выполнить прикладную операцию.

```json
{
  "op": "COMMAND",
  "request_id": "01K00000000000000000000001",
  "type": "message.create",
  "data": {
    "conversation_id": "01J00000000000000000000001",
    "content": {
      "type": "text",
      "text": "Hello!"
    }
  }
}
```

`request_id` MUST уникально идентифицировать незавершённый запрос в пределах клиентской сессии.

Для каждого принятого `request_id` сервер MUST сформировать не более одного итогового `RESULT`.

## RESULT

`RESULT` сопоставляется с ранее отправленной командой.

Пример успешного результата:

```json
{
  "op": "RESULT",
  "request_id": "01K00000000000000000000001",
  "status": "ok"
}
```

Пример отклонения:

```json
{
  "op": "RESULT",
  "request_id": "01K00000000000000000000001",
  "status": "error",
  "error": {
    "code": "PERMISSION_DENIED",
    "message": "The current user cannot perform this operation."
  }
}
```

Успешный `RESULT` означает, что команда была принята и обработана в соответствии с семантикой сервера. Для применения изменений общего состояния клиенты MUST использовать авторитетные пакеты `EVENT`, а не `RESULT`, если только операция явно не определена как исключительно запрос данных.

## EVENT

`EVENT` описывает авторитетное изменение состояния.

```json
{
  "op": "EVENT",
  "seq": 1582,
  "type": "message.created",
  "data": {
    "id": "01K00000000000000000000002",
    "conversation_id": "01J00000000000000000000001",
    "author_id": "01H00000000000000000000001",
    "content": {
      "type": "text",
      "text": "Hello!"
    }
  }
}
```

В пределах одной области синхронизации значения `seq` MUST монотонно возрастать.

Клиент, обнаруживший разрыв последовательности, MUST NOT считать, что пропущенного состояния не существует. Перед тем как снова считать своё локальное состояние авторитетным, он SHOULD запросить синхронизацию или восстановление.

## ACK

`ACK` подтверждает, что клиент успешно применил события до указанного значения последовательности включительно.

```json
{
  "op": "ACK",
  "seq": 1582
}
```

В v0.1 семантика ACK является накопительной.

## RESUME

`RESUME` запрашивает продолжение после последней применённой клиентом последовательности.

```json
{
  "op": "RESUME",
  "after": 1582
}
```

Сервер может повторно передать последующие события либо вернуть ошибку, указывающую на необходимость полной синхронизации.

## HEARTBEAT

Любая сторона может отправить:

```json
{
  "op": "HEARTBEAT",
  "nonce": "01K00000000000000000000003"
}
```

Другая сторона SHOULD ответить с тем же nonce:

```json
{
  "op": "HEARTBEAT",
  "nonce": "01K00000000000000000000003",
  "reply": true
}
```

Реализации MUST предотвращать циклы heartbeat-запросов. Пакет, содержащий `"reply": true`, является ответом и MUST NOT сам вызывать новый heartbeat-ответ.

## ERROR

`ERROR` представляет ошибку уровня протокола, а не ошибку выполнения прикладной команды.

```json
{
  "op": "ERROR",
  "code": "INVALID_STATE",
  "message": "Packet is not valid in the current connection state."
}
```

Ошибки приложения, связанные с `COMMAND`, SHOULD обычно передаваться через соответствующий пакет `RESULT`.

## Соглашения об именовании

Операции верхнего уровня используют имена в верхнем регистре, например `COMMAND` и `EVENT`.

Типы прикладных команд используют пространства имён в нижнем регистре с точками:

```text
message.create
message.edit
member.ban
reaction.add
```

Типы авторитетных событий SHOULD по возможности использовать форму завершённого состояния:

```text
message.created
message.edited
member.banned
reaction.added
```
