# Morph Protocol v0.1 — Восстановление событий

Каноническая спецификация. Capability: `sync-cursor-v1`.

Поток EVENT общий для соединений одного пользователя в одном развёртывании API.
seq — безопасное целое JSON ≥ 0; первый EVENT имеет seq = 1. Курсор MUST NOT
переиспользоваться для другого аккаунта или развёртывания.

Присвоение seq, запись события и ограничение журнала MUST быть атомарными.
Чтение текущего seq и журнала MUST возвращать согласованный снимок.
Morph использует Redis Lua. Pub/sub и replay могут доставлять события повторно
или менять порядок: клиент восстанавливает его по seq.

## Начальная синхронизация

При согласованной capability READY содержит текущий seq пользователя.
READY MUST предшествовать живым EVENT на соединении. Клиент без локального состояния
сохраняет временную границу, загружает HTTPS-снимки диалогов, открытой истории сообщений
и звонков, затем применяет события выше границы. На время загрузки события буферизуются.
Курсор принимается только после успешной синхронизации и MUST NOT храниться отдельно
от соответствующего состояния. Закрытие соединения отменяет его запросы снимка.

## Переподключение

При сохранённом состоянии клиент выполняет RESUME после READY с последним применённым
seq. События с меньшими номерами — дубликаты. Пропуск требует буферизации и RESUME;
ACK MUST NOT перескакивать через пропуск. Применение последовательное, ACK отправляется
после успешного применения. Восстановление заканчивается при достижении READY.seq.
Для пропуска на готовом соединении цель — наибольший полученный seq.

Если непрерывный диапазон недоступен, сервер возвращает:

```json
{"op":"ERROR","code":"SYNC_FULL_REQUIRED","message":"Stored event history is insufficient for resume.","seq":2500}
```

Клиент получает полный снимок с новой границей по правилам начальной синхронизации.
Уменьшение seq после сброса Redis также требует полного снимка. REALTIME_UNAVAILABLE
требует закрытия соединения и полной синхронизации после восстановления сервиса.
База API — источник полного состояния; Redis — ограниченный журнал для быстрого replay.

По умолчанию журнал хранит последние 1000 событий; TTL после последней записи — 24 часа.
Клиент ограничивает буфер 1000 событиями, ожидание синхронизации — 30 секундами.
Превышение требует нового соединения и полного снимка. Это не гарантия неограниченной
работы офлайн. Курсор и результат старого запроса MUST NOT затирать новое состояние
после переподключения.

## Heartbeat и ограничения

HEARTBEAT поддерживается после HELLO_ACK. Ответ MUST повторять nonce запроса и
содержать reply: true. Ответ не вызывает нового ответа. Другой nonce или обычное
событие не подтверждают ожидаемый heartbeat.

Интервал по умолчанию — 25 секунд. Клиент закрывает соединение, если heartbeat
не подтверждён к следующему интервалу. Сервер ждёт пакет не более трёх интервалов;
до READY таймаут одного чтения — 10 секунд.

HELLO_ACK.max_packet_bytes задаёт предел UTF-8 JSON-пакета, принимаемого сервером
(по умолчанию 65 536 байт). Превышение вызывает PACKET_TOO_LARGE и закрытие 1009.
Неизвестные поля игнорируются, неизвестные операции вызывают UNKNOWN_OPERATION.
