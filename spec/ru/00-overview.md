# Morph Protocol v0.1 — Обзор

> Этот документ является частью канонической русскоязычной спецификации Morph Protocol. При расхождениях с переводами приоритет имеет версия из `spec/ru/`.

Morph Protocol — прикладной протокол, используемый клиентами и серверами Morph для обмена командами, результатами, событиями, состоянием синхронизации и метаданными соединения.

Протокол определяет данные, переходы состояний и поведение системы. Он не определяет, как клиент должен отображать или представлять эти данные пользователю.

## Цели проектирования

Morph Protocol v0.1 строится вокруг следующих принципов:

- событийная синхронизация состояния;
- сессии с учётом устройств;
- независимость логического протокола от транспорта;
- независимость от представления и интерфейса;
- явное версионирование;
- возобновляемые realtime-сессии;
- расширяемость без обязательного нарушения совместимости со старыми клиентами;
- использование проверенных криптографических стандартов вместо собственных криптографических примитивов.

## Область v0.1

Первая экспериментальная версия использует:

- WebSocket как realtime-транспорт;
- TLS 1.3 для защиты транспорта;
- UTF-8 JSON для кодирования пакетов;
- модель command / result / event;
- синхронизацию и восстановление по последовательностям событий;
- heartbeat-сообщения для контроля активности соединения.

Следующие возможности намеренно не входят в v0.1 и могут быть добавлены позже:

- бинарное кодирование;
- Morph Secure Session;
- криптографическая идентичность устройства;
- сквозное шифрование;
- формат зашифрованных вложений;
- транспорт QUIC;
- пространства имён расширений.

## Жизненный цикл протокола

Типичное соединение проходит следующим образом:

```text
Client                                Server
  |                                      |
  |---- WebSocket over TLS ------------> |
  |---- HELLO -------------------------->|
  |<--- HELLO_ACK ---------------------- |
  |---- AUTH --------------------------->|
  |<--- READY -------------------------- |
  |                                      |
  |---- COMMAND ------------------------>|
  |<--- RESULT ------------------------- |
  |<--- EVENT -------------------------- |
  |---- ACK ---------------------------->|
  |                                      |
```

Повторно подключающийся клиент после аутентификации может использовать `RESUME`, чтобы запросить события, идущие после последней известной ему последовательности.

## Основная семантическая модель

Morph Protocol разделяет три понятия:

- **COMMAND** — клиент просит сервер выполнить операцию.
- **RESULT** — сервер сообщает, была ли команда принята или отклонена.
- **EVENT** — сервер сообщает, что авторитетное состояние системы изменилось.

Успешный `COMMAND` сам по себе не является изменением состояния. Изменение состояния представляет соответствующий `EVENT`.

Пример:

```text
COMMAND member.ban
RESULT  ok
EVENT   member.banned
```

Такое разделение позволяет клиентам согласованно восстанавливать состояние между несколькими устройствами и после переподключений.

## Статус версий

Все версии протокола `0.x` являются экспериментальными и могут содержать несовместимые изменения.

`1.0` станет первой стабильной версией спецификации.
